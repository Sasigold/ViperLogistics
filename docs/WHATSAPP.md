# עוזר וואטסאפ (0236)

שואלים את המערכת ומבקשים שינויים מתוך וואטסאפ: "מה יש מחר?", "כמה הכנסות
החודש?", "תזיז את ההקמה של כהן לשלישי ב-10:00". הבוט עונה בהרשאות של מי שכתב,
וכל שינוי מוצג קודם בשורות מדויקות ורץ רק אחרי "כן".

המספר הוא אותו מספר בוט של Viper One (Green API). קבוצת הוואטסאפ של Viper One
הפכה לקבוצה של ViperLogistics; Viper One ממשיך לקבל את כל השאר (ראו "Viper One"
למטה).

## מה בנוי איפה

| חלק | איפה |
|---|---|

| ה-webhook, הניתוב, התור, האישור | פונקציית קצה `whatsapp-webhook` (**`--no-verify-jwt`**) — `index.ts` |
| הרצה בשם המשתמש | `whatsapp-webhook/db.ts` (חיבור ישיר ל-Postgres) |
| הכלים (שאלות ושינויים) | `whatsapp-webhook/tools.ts` |
| הקריאה ל-Claude | `whatsapp-webhook/agent.ts` + `_shared/assistantLoop.ts` |
| ההנחיה, הקטלוג, שורות התצוגה | `_shared/assistant.ts` |
| פענוח ההודעה, הפקודות, הניתוב, זמן ישראל | `_shared/whatsapp.ts` (טהורים, נבדקים ב-vitest) |
| המסכים | "התראות" (`/my/notifications`): חיבור המספר שלי · "אינטגרציות" (`/integrations`): קבוצות, מי מחובר, הודעות אחרונות |

## איך זה עובד

1. **Green API שולח לכאן כל הודעה נכנסת.** הסוד נבדק (`Authorization: Bearer`),
   וגם שה-instance הוא שלנו.
2. **למי ההודעה שייכת** (`route` ב-`_shared/whatsapp.ts`):
   - קבוצה שמנהל חיבר — שלנו בלבד. לא מועברת ל-Viper One לעולם.
   - צ'אט פרטי של משתמש מקושר — שלנו. צ'אט פרטי חייב להיות של השולח עצמו.
   - "קוד 123456" בצ'אט פרטי — קישור. בקבוצה מחוברת הקוד נשרף מיד (כולם ראו אותו).
   - כל הודעה נכנסת אחרת — מועברת כמו שהיא ל-Viper One, אם הוגדר `WHATSAPP_FORWARD_URL`.
   - הודעות יוצאות, סטטוסים וריאקשנים — לא מעובדים ולא מועברים.
3. **בשם המשתמש.** כל כלי רץ בטרנזקציה עם `set local role authenticated` ו-`request.jwt.claims`
   של המשתמש — כמו בבדיקות ה-SQL — ולכן RLS, `app.has`, `app.require` והטריגרים פוסקים בדיוק
   כמו בדפדפן. המפתח `assistant.whatsapp` רק פותח את הערוץ; מה שמותר בו נקבע בשאר המפתחות.
4. **שינוי בשני שלבים.** כלי שינוי קורא את המצב, מריץ ניסיון של השינוי (ושל כל מה שהוכן איתו)
   בטרנזקציה שמתבטלת, ושומר אותו ב-`wa_pending`. המשתמש רואה שורות שהקוד כתב (לא המודל) ו"לאשר?".
   על "כן" — רק של מי שביקש, כהודעת טקסט חדשה, בתוך 15 דקות, ואחרי שההודעה נשלפה מחדש מהיומן
   של Green API (`getMessage`) — הפעולות השמורות רצות בטרנזקציה אחת, עם תנאי `updated_at` כמו בלוח.
5. **קבוצה.** הבוט עונה בקבוצה רק כשכל המשתתפים בה הם משתמשים מקושרים ופעילים (`getGroupData`,
   נבדק בחיבור ושוב כל שעה). נתוני כסף בקבוצה — רק כשלכל המשתתפים יש את המפתח הרלוונטי.
6. **תור.** מחזירים 200 מיד ומעבדים ברקע; הודעה אחת בכל רגע לכל צ'אט (`wa_chats.busy_until`),
   השאר ממתינות בתור (`wa_messages.status = 'queued'`). כל `idMessage` מעובד פעם אחת.

## מה הבוט יודע (גרסה ראשונה)

**שאלות:** אירועים (חיפוש), פרטי אירוע ומשימותיו, לו״ז לטווח (כולל "מה חסר"), הכנסות ורווח
(כמו הכרטיסים בדשבורד), כמה לקוחות חייבים, תשלומי אירוע, ארנק מזומן, משימות ניהול, אנשי צוות.

**שינויים (תמיד באישור):** תאריך/שעות של משימה, הזזת אירוע (עם ההקמה והפירוק), משימה חדשה,
שיבוץ והסרה של עובד/נהג/ראש צוות, סטטוס ופרסום, משימות ניהול (יצירה, סימון כבוצעה, דחייה),
תשלום על אירוע, חיוב נוסף, תנועה בארנק המזומן, הערה ביומן האירוע, וחשבונית ספק מצילום/PDF
(נקראת לפני האישור ונשמרת בעמוד החשבוניות).

**לא כאן:** מחיקה וביטול, אירוע חדש, העברה לקבלן, מחירים, תלושים, משתמשים והרשאות, הודעות קוליות.

## הפעלה בייצור — פעם אחת

1. **מיגרציה** `0236_whatsapp_assistant.sql` (דרך `apply_migration`; אין בה `drop` ואין `delete`).
2. **פריסה:** `supabase functions deploy whatsapp-webhook --no-verify-jwt`.
3. **סודות** (Supabase → Edge Functions → Secrets):

   | סוד | מה |
   |---|---|
   | `WHATSAPP_WEBHOOK_SECRET` | מחרוזת אקראית ארוכה שתמציאו (למשל `openssl rand -hex 24`) |
   | `GREENAPI_ID_INSTANCE`, `GREENAPI_API_TOKEN_INSTANCE` | מהקונסולה של Green API — אותו instance של Viper One |
   | `GREENAPI_API_URL` | רשות: ה-apiUrl שמופיע בקונסולה, אם הוא לא `https://api.green-api.com` |
   | `WHATSAPP_FORWARD_URL` | רשות, מומלץ: כתובת ה-webhook **הנוכחית** שמופיעה ב-Green API (של Viper One, כולל `?token=`) |
   | `APP_URL` | רשות: ברירת המחדל `https://viper-logistics.vercel.app` (לקישורים בתשובות) |
   | `ASSISTANT_MODEL`, `ASSISTANT_EFFORT` | רשות: ברירת המחדל `claude-sonnet-5-5` ו-`medium` |

   `ANTHROPIC_API_KEY` כבר מוגדר (`payslip-read`, `invoice-read`).
4. **Green API → Settings:**
   - Webhook URL: `https://qdrbhwxnijjmprtzxfai.supabase.co/functions/v1/whatsapp-webhook`
   - Webhook URL token: הערך של `WHATSAPP_WEBHOOK_SECRET` (עם `Bearer ` לפניו או בלי — שניהם עובדים)
   - Incoming messages: Yes.
   - כדאי לוודא שהמסלול של Green API אינו מגביל את מספר הצ'אטים — צ'אט הקישור הפרטי נספר.
5. **הרשאה:** מנהלי מערכת מחזיקים בה. לאנשי משרד — "עוזר וואטסאפ" במטריצת ההרשאות.
6. **חיבור:** עמוד "התראות" ← "חבר את הוואטסאפ שלי" ← שולחים את הקוד לבוט בפרטי. אחר כך,
   בקבוצה: "הפעל כאן".

**ביטול מלא:** מחזירים ב-Green API את כתובת ה-webhook הקודמת (של Viper One). הכול חוזר להיות כמו לפני.

## Viper One

Viper One מקבל מכאן כל הודעה נכנסת שאינה שלנו, בייט-בייט, לכתובת שב-`WHATSAPP_FORWARD_URL`.
הקבוצה שחוברה ל-ViperLogistics כבר לא מגיעה אליו. כדי להמשיך לרשום בו הוצאות בוואטסאפ: פותחים
קבוצה חדשה עם הבוט וכותבים בה "קבע קבוצה" — זה עובר אליו, והוא עובר לעבוד בה.

## תקלות

| מה רואים | למה | מה עושים |
|---|---|---|
| הבוט לא עונה בכלל | הסוד לא תואם (401 ביומן הפונקציה) או ש-Green API עדיין מצביע על Viper One | לבדוק את Webhook URL ואת ה-token ב-Green API |
| "לא הצלחתי לאמת את האישור" | ההודעה עוד לא הופיעה ביומן של Green API (עד 2 דקות) | לשלוח "כן" שוב |
| "אני לא עונה בקבוצה הזו כרגע" | יש בקבוצה משתתף לא מקושר | לקשר אותו או להוציא אותו; או לכתוב לבוט בפרטי |
| "חסר מפתח AI" | `ANTHROPIC_API_KEY` לא מוגדר | להגדיר את הסוד |
| הכלי נכשל עם הודעה מהמסד | ההרשאה חסרה או שהנתונים השתנו | ההודעה אומרת מה; כל מה שקרה רשום ב"אינטגרציות" ← וואטסאפ |

## עלות

ברירת המחדל `claude-sonnet-5-5` (בחירת הבעלים: זול מ-Opus בערך בחצי). הודעה רגילה היא 2–4 קריאות,
בערך $0.02–$0.05. `ASSISTANT_MODEL=claude-opus-5-5` בסודות הפונקציה מחזיר את Opus. תקרה: 60 הודעות
לשעה למשתמש.
